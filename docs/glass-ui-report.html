Recommendation

Asgard 2.2.0

Use Haze in the optional asgard-glass add-on. Register the background once and apply frost to each chosen component. Lens refraction remains a future experiment.

Glass earns its place where a control floats over content that moves beneath it. Frost softens background detail so the label stays readable. Refraction also bends that detail near the edges. A bar over an empty scaffold inset has little to sample. Place the feed behind the bar and reserve enough scroll padding to reach the last item. Apple’s material guidance likewise places glass in a distinct layer for navigation and controls. Apple material guidance

Asgard already gets its colors, shapes and typography from the host’s Material theme. Keep that contract. Installing the add-on should only make glass available. Each component instance explicitly selects it, and the host can turn it off for accessibility or by user preference. The core artifact can continue to ship without a renderer dependency. Renderer comparison

All three libraries publish Android and Wasm variants under Apache 2.0. Haze is the best fit for starting with frost and adding a lens later through the same source registration. Repository stars below are rounded adoption signals observed on 22 November 2026.

Haze 2.1.0

≈2.7k GitHub stars

First choice. Core tracks source layers. Separate haze-blur and haze-glass modules provide frost and refraction. The 2.1.0 artifacts declare Kotlin 2.4.21 and Compose 1.12.2. A sample using both modules compiled with Asgard’s newer Compose pin. Ship core and blur for the first style, then add the glass module when the lens is ready.

Release Published variants Glass behavior

Backdrop 2.0.1

≈4.7k GitHub stars

Best alternative for bespoke optics. Kyant’s io.github.kyant0:backdrop provides composable blur, lens, highlights and layer backdrops. Android blur requires API 31 and the lens requires API 33. Its 2.x line publishes both Asgard targets. It suits a team that wants to art-direct the material and own its presets and fallbacks.

Project Effect guide Published variants Android sources

Liquid 1.1.1

≈580 GitHub stars

Focused lens alternative. FletchMcKee’s liquid pairs an explicit source with an effect modifier and offers shader-driven distortion. It publishes the required variants. Its metadata targets Kotlin 2.3.0 and Compose 1.10.0, a wider version gap to exercise if Asgard chooses this engine.

Compose alone

Built-in fallback

A theme-colored fill and outline are cheap and predictable on every Asgard target. Compose’s Modifier.blur() softens the contents of its own layer, including any text drawn there. Backdrop frost needs a separately sampled background with sharp controls drawn over it. Building that pipeline in Asgard would also make Asgard responsible for capture, coordinates and platform differences.

Opt-in API

Register the image or scrolling content with asgardGlassSource. Put a glass modifier on each chosen control. This example uses an app-provided photo and tap handler. The card keeps its own text colors and click handling.

Kotlin · opt-in metric card
val shape = MaterialTheme.shapes.large
val fill = MaterialTheme.colorScheme.surfaceContainer
val source = rememberAsgardGlassSource(enabled = glassCard && !reduceTransparency)
Box {
    Photo(Modifier.matchParentSize().asgardGlassSource(source))
    AsgardStatCard(
        label = "Voltage", value = "5.00", unit = "V",
        modifier = Modifier.asgardGlass(source, enabled = glassCard, shape = shape, containerColor = fill),
        shape = shape,
        containerColor = if (glassCard) Color.Transparent else fill,
        onClick = openVoltageDetails,
    )
}

Where to place the effect

The source records just the background subtree, such as the scrolling list. The overlay samples that source in the same coordinate space, clips and tints it inside its resolved container shape, then draws icons and labels above it. Keep overlays outside their own source and share one recording across the chosen surfaces. A missing or disabled source uses the ordinary Material fill. Haze core concepts

What belongs in each artifact

Core Asgard exposes a container slot on the toolbar and configured navigation bar. It draws inside the control’s shape and insets. The add-on supplies source.frosted(enabled), Modifier.asgardGlass, and AsgardGlassSurface for content slots. Applications using core alone can keep their current dependencies.

Evidence & release checks

Asgard 2.2.0 includes per-component previews and a shared rating table used by both galleries and the Asgard skill. The implementation guide gives the current API and Android fallback policy. Glass UI integration guide

Release candidate verification. All 38 app tests passed on the API 36 emulator, including a switch check for all 54 gallery entries. Four glass tests passed on the API 28 solid fallback. In the Wasm gallery, Chromium rendered the frosted tile and restored its solid fill when reduced transparency was enabled. Optimized physical-device and browser frame costs still need measurement.
1. Exercise the same scene in both galleries.
Use the shared gallery’s glacier scene to exercise scrolling beneath the toolbar and floating bar. Independently toggle each surface and switch to the solid fallback. Check rest, fast scroll, route changes, RTL, resizing and clipped custom shapes. An area outside the selected surface should match the solid baseline. Existing gallery harness
2. Check legibility against the worst backdrop.
Try bright photos, dark photos and dense text in both host themes. Measure the composited pixels behind labels. Target 4.5:1 for ordinary text, 3:1 for large text and 3:1 for required control boundaries or state indicators. Use explicit host content colors and a stronger tint or opaque fill when needed. Honor reduced transparency through an app preference and available platform signals. Disable optional animated highlights under reduced motion. Check focus, TalkBack, touch targets and 200% text scaling in both modes. Text contrast · Non-text contrast
3. Measure cost per selected surface.
Compare the same scrolling workload with zero, one and two glass surfaces on physical Android devices spanning the three API tiers and in the Wasm gallery. Record frame-time percentiles, missed deadlines, GPU time where available, memory and artifact size. Agree a regression budget against the plain baseline before shipping. Profile API 31 during an unrelated animation. If a tier misses its budget, ship the solid fallback there. Asgard’s existing emulator measurements cover other components. Asgard benchmark method · Haze performance guidance
4. Verify the published consumer paths.
Resolve core alone and confirm its dependency graph excludes Haze. Resolve the add-on from a test Maven repository on both targets. Run the compatibility fixture and extend it with a toolbar and configured navigation call compiled against 2.1.1. Ship frost when these checks pass. Evaluate lens distortion against the same scenes and budget before exposing it. Existing compatibility fixture
